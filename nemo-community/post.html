深入理解 JavaScript 事件循环机制：从宏任务到微任务的完整解析

📅 2024年1月15日 📁 编程开发 👁 2,341 阅读 ❤ 128 点赞 💬 36 评论

JavaScript 作为一门单线程语言，却能够处理异步操作，这背后的核心就是事件循环（Event Loop）机制。理解事件循环不仅是面试中的高频考点，更是我们写出高效、正确的异步代码的基础。

一、为什么需要事件循环？

JavaScript 最初被设计为浏览器中的脚本语言，主要用于处理用户交互、操作 DOM。如果 JavaScript 是多线程的，那么在一个线程修改 DOM 的同时另一个线程删除 DOM，就会产生复杂的同步问题。因此，JavaScript 选择了单线程的设计。

单线程意味着所有任务需要排队执行，前一个任务结束，后一个任务才会开始。但如果某个任务耗时很长（比如网络请求），后面的任务就必须等待，这会导致页面卡顿，用户体验极差。

为了解决这个问题，JavaScript 引入了异步机制，而事件循环就是实现异步的核心原理。

二、调用栈与任务队列

在理解事件循环之前，我们需要先了解两个重要的概念：调用栈（Call Stack）和任务队列（Task Queue）。

2.1 调用栈

调用栈是 JavaScript 执行代码的地方。当函数被调用时，它会被推入栈顶；当函数执行完毕时，它会从栈顶弹出。这是一个典型的"后进先出"（LIFO）结构。

function foo() {
  console.log('foo');
  bar();
}

function bar() {
  console.log('bar');
}

foo();
console.log('global');

上面这段代码的执行顺序是：

  • 全局执行上下文入栈，执行 foo()
  • foo 函数入栈，打印 'foo'，然后调用 bar()
  • bar 函数入栈，打印 'bar'，执行完毕出栈
  • foo 函数执行完毕出栈
  • 继续执行全局代码，打印 'global'

2.2 任务队列

当遇到异步操作（如 setTimeout、网络请求、DOM 事件等）时，这些操作不会阻塞主线程，而是会在合适的时机将回调函数放入任务队列中，等待调用栈清空后执行。

三、宏任务与微任务

任务队列中的任务又分为两种：宏任务（MacroTask）和微任务（MicroTask）。它们的执行顺序是事件循环中最关键的部分。

3.1 常见的宏任务

  • script（整体代码）
  • setTimeout / setInterval
  • I/O 操作
  • UI 渲染
  • setImmediate（Node.js）

3.2 常见的微任务

  • Promise.then / catch / finally
  • process.nextTick（Node.js）
  • queueMicrotask
  • MutationObserver

四、事件循环的执行顺序

事件循环的执行规则可以概括为以下几点：

  1. 从宏任务队列中取出一个任务执行
  2. 执行过程中如果遇到微任务，将其加入微任务队列
  3. 当前宏任务执行完毕后，依次执行微任务队列中的所有任务
  4. 微任务全部执行完毕后，进行 UI 渲染（如果需要）
  5. 然后进入下一轮循环，从宏任务队列取下一个任务

简单来说就是：先执行一个宏任务，然后把所有微任务都执行完，再执行下一个宏任务。

console.log('1');

setTimeout(function() {
  console.log('2');
  Promise.resolve().then(function() {
    console.log('3');
  });
}, 0);

Promise.resolve().then(function() {
  console.log('4');
});

console.log('5');

让我们来分析一下这段代码的执行顺序：

  1. 执行全局 script（宏任务），打印 '1'
  2. 遇到 setTimeout，将回调放入宏任务队列
  3. 遇到 Promise.then，将回调放入微任务队列
  4. 继续执行，打印 '5'
  5. 当前宏任务（script）执行完毕，开始执行微任务队列
  6. 执行 Promise 回调，打印 '4'
  7. 微任务队列清空，进入下一轮循环
  8. 执行 setTimeout 回调（宏任务），打印 '2'
  9. 遇到 Promise.then，放入微任务队列
  10. 当前宏任务执行完毕，执行微任务
  11. 执行 Promise 回调，打印 '3'

所以最终的输出顺序是：1, 5, 4, 2, 3

五、Node.js 中的事件循环

Node.js 中的事件循环与浏览器略有不同，它有更多的阶段，并且微任务的优先级也有所区别。Node.js 的事件循环分为6个阶段：

  • timers：执行 setTimeout 和 setInterval 的回调
  • pending callbacks：执行延迟到下一个循环的 I/O 回调
  • idle, prepare：仅内部使用
  • poll：获取新的 I/O 事件
  • check：执行 setImmediate 的回调
  • close callbacks：执行关闭事件的回调

在 Node.js 中，process.nextTick 的优先级高于 Promise，也就是说 nextTick 队列会在微任务队列之前执行。

六、总结

事件循环是 JavaScript 异步编程的核心机制。理解宏任务和微任务的执行顺序，能够帮助我们：

  • 写出更可预期的异步代码
  • 快速定位异步相关的 bug
  • 在面试中脱颖而出
  • 更好地理解 Promise、async/await 等高级特性
